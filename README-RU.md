# VPN и панель одной командой

Это документация **1.1-dev**, не опубликованного релиза. [Изменения и команда тестового обновления](CHANGELOG-1.1-RU.md), [сравнение vless.wiki](VLESS-WIKI-REVIEW-RU.md), [обрывы на iPhone](IOS-RU.md). Ссылки установки с `/main/` ниже относятся к основному выпуску 1.0.

Целевой сервер: **Ubuntu 22.04**, systemd, x86_64 или ARM64, два публичных IPv4 и домен. Данные предыдущего VPS в код не зашиты. Также предусмотрены Ubuntu 24.04 и Debian 12/13.

## Запуск

Войдите на новый VPS по SSH. Полная команда с автоматической установкой curl находится в [кратком гайде на главной странице](README.md#полная-команда). Если curl уже есть:

```bash
curl -fsSL https://raw.githubusercontent.com/grislytoe/vless-server-kit/main/start.sh | sudo bash
```

Запуск из переданного каталога:

```bash
sudo bash install.sh --check
sudo bash install.sh --install
```

Интерактивный запускатель выполнит обе стадии сам и запросит:

1. Заранее настроенный домен или поддомен, например `vpn.example.com`, без `https://` и пути.
2. **Основной (первый) публичный IPv4 сервера** — поле `Incoming public IPv4`. На него должна указывать DNS A выбранного домена; он принимает входящие подключения на TCP 443.
3. **Второй, дополнительный публичный IPv4 того же сервера** — поле `Second public IPv4`, для исходящих подключений VPN.
4. Логин панели: 3–40 латинских букв, цифр, `_` или `-`.
5. Пароль панели и повтор: 16–256 символов, ввод скрыт.

Адреса и логин можно редактировать стрелками, Home и Backspace. При ошибке формата повторяется только соответствующее поле. Если пароль слишком короткий/длинный или повтор не совпал, скрипт объяснит причину и предложит повторить ввод пароля, сохранив логин и параметры сервера. В скрытом пароле используйте Backspace или Ctrl+U для очистки всей строки; пароль на экран не выводится.

Назначенные серверу IPv4 выводятся как подсказка. Логин и пароль вводятся перед установкой основных компонентов. При обновлении существующей установки они сохраняются. Ввод идёт через `/dev/tty`, поэтому работает и при запуске `curl … | sudo bash`; для удалённой SSH-команды нужен `ssh -t`.

При прямом запуске `install.sh` допустимы `--domain=... --inbound=... --outbound=...`: `--inbound` — основной IP, `--outbound` — второй. Публичная команда с `start.sh` запрашивает параметры интерактивно. Пароль в аргументах и переменных окружения не передаётся.

## Что подготовить

- Чистый выделенный VPS Ubuntu 22.04 с systemd, root либо sudo.
- Два разных публичных IPv4, назначенных интерфейсу и маршрутизируемых хостером. NAT, подменяющий исходящий IP, не подходит.
- Зарегистрированный домен или поддомен с прямой DNS A на **основной (первый) публичный IPv4 сервера**, без CDN-проксирования; AAAA должна отсутствовать.
- Входящие TCP 80 и 443, работающий SSH, исходящий HTTPS и UDP DNS.

До запуска скрипта в DNS-зоне домена создайте A-запись на основной публичный IPv4 VPS. Для самого домена обычно указывают имя `@`, для `vpn.example.com` — `vpn`. Среди A-записей выбранного имени должен быть только основной адрес. Удалите AAAA для этого имени, отключите CDN-проксирование и дождитесь применения DNS. Второй IPv4 в A-запись домена панели/VPN не добавляйте.

**Сначала вводится основной публичный IP, затем второй, дополнительный.** Основной адрес уточните в панели хостера; обычно по нему выполняется подключение по SSH. Порядок вывода адресов интерфейса не гарантирует, что основной будет показан первым.

Запускатель устанавливает базовые зависимости через APT при необходимости. Настройка DNS и покупка/назначение второго IP выполняются у провайдера. Скрипт проверяет ОС, архитектуру, DNS A/AAAA, интерфейсы, маршрут, фактический исходящий IPv4 и порты. При обнаружении чужого Nginx/Xray/Selfsteal он останавливается до изменений. Firewall, SSH, MTU, BBR и TCP-буферы автоматически не меняются; состояние BBR и очереди выводится для проверки.

## Панель

После установки выводится URL вида `https://ваш-домен/manage-<случайный-путь>/`. Сохраните его с выбранным паролем. С главной страницы ссылка на панель не публикуется.

В панели доступны список всех созданных ключей и их состояний, создание ключа с названием устройства, копирование VLESS-ссылки, скачивание PNG QR для HAPP, деактивация и окончательное удаление. Неактивные ключи остаются в списке без рабочей ссылки; удалённые исчезают. Для каждого клиента создаётся отдельный UUID; серверная пара REALITY общая для сервера. Лимит — 500 записей, включая неактивные. Чтобы снова выдать доступ, создайте новый ключ.

**Каждое изменение ключей перезапускает Xray:** это отзывает уже открытые соединения удалённого/деактивированного клиента. Остальные устройства могут кратко переподключиться.

После создания, деактивации и удаления ключа панель показывает ход операции, проверяет результат после восстановления соединения и обновляет список и счётчики прямо на странице без её перезагрузки. Запрос изменения отправляется один раз. Рядом со скачиванием QR видна сканируемая миниатюра с белым полем; скачивается версия PNG большего разрешения. Для обновления списка требуется JavaScript.

Панель работает без root через Gunicorn и Unix-сокет. Отдельная root-служба `vless-admin` проверяет UID вызывающего процесса и принимает только ограниченные команды управления ключами. Она проверяет конфиг настоящим Xray и восстанавливает прежние файлы при ошибке. Незавершённые операции имеют журнал восстановления; установка и изменение ключей используют общий lock.

Пароль хранится как scrypt-хеш с солью. Новые пароли используют N=32768, r=8, p=3; существующий хеш сохраняется до смены пароля. Есть CSRF-защита, Secure/HttpOnly/SameSite cookie и серверный срок сессии 30 минут. Выход отзывает сессию, включая сохранённую копию cookie. Счётчики попыток входа хранятся в SQLite и сохраняются при перезапуске: пять проверок на адрес/операцию за 15 минут, общий предел 60 за минуту. REALITY передаёт адрес клиента локальному Nginx через PROXY protocol; входящие forwarded-заголовки очищаются. Ссылки/QR требуют входа и не кэшируются. Access-log панели отключён.

Gunicorn 27.0.0 устанавливается в отдельное окружение `/opt/vless-runtime/` из официального wheel с проверкой SHA256. Системные библиотеки веб-приложения обновляются через APT. [Отчёт проверки безопасности](SECURITY-RU.md) описывает исправления, тесты и границы защиты.

Из панели пароль меняется кнопкой «Сменить пароль» в правом верхнем углу: укажите текущий пароль и дважды новый (16–256 символов). После сохранения потребуется повторный вход на всех устройствах. VPN-ключи не меняются, службы VPN при смене пароля не перезапускаются. Если текущий пароль забыт, воспользуйтесь SSH-командами ниже.

```bash
sudo python3 /opt/vless-optimized/panel_setup.py --reset
sudo systemctl restart vless-panel
```

После перезапуска старые сессии прекращают действовать. Восстановление URL панели:

```bash
sudo python3 -c 'import json; s=json.load(open("/var/lib/vless-optimized/settings.json")); print("https://"+s["domain"]+s["panel_path"]+"/")'
```

## Соединение

```text
HAPP → первый IP:443 → Xray VLESS + XHTTP + REALITY → второй IP → интернет
Браузер → домен:443 → REALITY fallback → Nginx 127.0.0.1:26869
                                     ├─ обычная страница
                                     └─ случайный путь панели → Unix-сокет Gunicorn
Certbot HTTP-01 → первый IP:80 → Nginx → продление сертификата
```

Xray закреплён на 26.11.9 с официальным SHA256 для каждой архитектуры. XHTTP `auto`, штатные XMUX и padding, без mux.cool и серверной фрагментации. Новые профили используют `fp=chrome`; старой установке сохраняется Firefox. [Анализ протокола и ограничений](PROTOCOL-RU.md) объясняет выбор. Нераспознаваемость или максимальная скорость в любой сети не гарантируются.

## Обновление, данные и резервные копии

Повторный запуск на управляемом сервере сохраняет UUID, REALITY-ключи, XHTTP-путь, клиентов, логин/пароль и путь панели. Домен и IP должны совпадать с сохранёнными. Первоначальный UUID старого комплекта переносится в список клиентов без смены ссылки. Его отзыв не отменяется повторной установкой. Чужие Docker/3X-UI/другие конфигурации автоматически не мигрируются.

| Путь на VPS | Содержимое |
|---|---|
| `/var/lib/vless-optimized/settings.json` | домен, IP, профиль, путь панели |
| `/var/lib/vless-optimized/credentials.json` | приватный ключ REALITY и исходные реквизиты |
| `/var/lib/vless-optimized/clients.json` | UUID и состояния клиентов |
| `/etc/vless-panel/admin.json` | хеш пароля и секрет сессии |
| `/var/lib/vless-panel/security.sqlite3` | реестр сессий и счётчики попыток входа |
| `/var/lib/vless-optimized/backups/` | резервные копии установки |
| `/usr/local/etc/xray/config.json` | действующий конфиг Xray |

Не публикуйте эти файлы и резервные копии. Локальные клиентские файлы храните в игнорируемом `connection/<домен>/`. В репозитории нет действующих реквизитов.

При обычной ошибке установки возвращаются управляемые файлы и прежние состояния служб. APT-пакеты, сертификаты и созданные VPN-реквизиты сохраняются для повторной попытки. SIGKILL/отключение питания не дают shell выполнить откат установки: перед повторным запуском проверьте сервер. Для изменений ключей предусмотрен отдельный журнал восстановления.

Если VPS не скачивает Xray с GitHub, передайте комплект и официальный архив через SFTP, затем запустите `sudo bash install.sh --install --archive=/root/Xray-linux-64.zip` из каталога комплекта; для ARM64 укажите соответствующий архив. SHA256 проверяется в любом случае. Опция `--archive` относится к `install.sh`, а публичный `start.sh` работает интерактивно и скачивает Xray сам.

## Проверки

Установка проверяет TLS 1.3/H2, работу и автозапуск служб, HTTPS-вход в панель, туннель и исходящий IP, UDP DNS через туннель, а также `certbot renew --dry-run --no-random-sleep-on-renew`. Если при повторном запуске нет активных ключей, туннельная/UDP-проверка явно пропускается: создайте ключ и повторите `probe.py`.

```bash
sudo systemctl status xray nginx vless-admin vless-panel certbot.timer --no-pager
sudo journalctl -u xray -u vless-admin -u vless-panel -n 80 --no-pager
sudo certbot renew --dry-run --no-random-sleep-on-renew
sudo python3 /путь/к/комплекту/probe.py --xray /usr/local/bin/xray --settings /var/lib/vless-optimized/settings.json --credentials /var/lib/vless-optimized/credentials.json
tc qdisc show
sysctl net.ipv4.tcp_congestion_control net.ipv4.tcp_available_congestion_control
```

Проверка с VPS не заменяет внешний тест. В HAPP на устройстве пользователя отдельно проверьте загрузку/отдачу, RTT, задержку под нагрузкой, UDP, простой, переподключение, смену сети и перезагрузку VPS. Записывайте точку измерения и версии HAPP/ядра. BBR/fq/MTU/XMUX меняйте только после выявленной проблемы, по одному фактору с повторным замером.

Локальные тесты проверяют конфиги настоящим Xray, вход/CSRF/QR/CRUD панели, откат и восстановление менеджера и shell-откат. Интеграционный стенд с настоящими Nginx/Xray проверяет TLS 1.3/H2, неверный SNI, 4 МиБ в обе стороны с проверкой содержимого, UDP, исходящий адрес, два UUID и отказ отозванному UUID. GitHub Actions повторяет эти тесты на Linux x86_64/ARM64. Это функциональные проверки, а не полный тест APT/ACME на новом VPS или замер скорости пользователя.
