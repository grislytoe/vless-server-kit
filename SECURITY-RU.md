# Аудит безопасности комплекта — 11 ноября 2026

Проверены все исполняемые файлы рабочего комплекта, шаблоны/JavaScript/CSS, конфиги Xray/Nginx/systemd, запускатели и тесты. Проверка относится к опубликованному коду и изолированным стендам; действующий пользовательский VPS по SSH в ходе аудита не исследовался. Это не независимый пентест и не обещание отсутствия неизвестных ошибок.

## Исправленные проблемы

| Проблема | Исправление | Проверка |

## Дополнительно проверено

- CSRF и проверка Origin сохраняются, включая формы входа и смены пароля. Отправка старой формы требует повторного входа/обновления формы. Заголовок `same-origin` сохраняет совместимость с настоящим браузером.
- Смена пароля проверяется привилегированным менеджером повторно и меняет версию авторизации: старые сессии прекращают действовать на следующем запросе. Пароли не передаются через командную строку и не сохраняются открытым текстом.
- UUID и пути проверяются; root RPC допускает ограниченный набор команд и проверяет UID процесса по `SO_PEERCRED`. Командная оболочка для запросов панели не используется.
- При отзыве клиента Xray перезапускается: открытые VPN-потоки отозванного UUID закрываются. UI не повторяет потерянный запрос создания ключа, а проверяет идентификатор операции.
- Имена клиентов экранируются шаблонизатором, сообщения JavaScript вставляются через `textContent`. Проверены XSS-строки, отсутствие доступа без входа, CSRF/чужой Origin и traversal статических файлов.
- Ссылки/QR выдаются только после входа, с запретом кэширования; QR генерируется локально. Секретный путь панели исключён из access-log и при переходе без завершающего `/`.
- Сертификаты проверяются по цепочке CA и имени, TLS fallback поддерживает TLS 1.3/H2. Неверный SNI отклоняется. Рабочие настройки не используют `allowInsecure` и не отключают проверку сертификата.
- В закреплённом Xray остаётся встроенная защита Freedom от private/reserved назначений для VLESS. Исключения для loopback присутствуют только в изолированном интеграционном тесте.
- Архивы Xray закреплены по версии/архитектуре и SHA256. Nginx устанавливается через подписанный репозиторий; ключ репозитория проверяется по SHA256. APT явно обновляет используемые библиотеки Flask/Werkzeug/Jinja/ItsDangerous/MarkupSafe/Pillow.
- Статический анализ Bandit разобран вручную: замечания об `subprocess` относятся к фиксированным аргументам без shell; `0660` относится к закрытому Unix-сокету с проверкой UID; строка `0.0.0.0` в UDP-пробе — проверка ответа SOCKS, а не публичное связывание сокета. Эти замечания не выдаются за автоматически доказанное отсутствие уязвимостей.

## Границы проверки и эксплуатация

- На конкретном VPS отдельно нужны проверка действующих файлов/владельцев, firewall и SSH, обновлений ОС/ядра, журналов, сертификата/ACME и внешнего туннеля с устройства пользователя. CI проверяет функциональность и права на временных Linux-машинах, а не фактическое состояние вашего VPS.
- После обновления старые cookie без серверного идентификатора сессии потребуют нового входа. Смена VPN-ключей всё ещё кратко перезапускает Xray.
- Защита от подбора не устраняет сетевой DDoS; распределённая атака может временно занять общий лимит входа. Для ограничения трафика до VPS используются средства хостера.
- Компрометация учётной записи панели даёт управление VPN-ключами. Компрометация её процесса позволяет читать доступные ему секреты; изоляция ограничивает последствия, но не заменяет исправления зависимостей и ОС.
- Публичный запускатель доверяет HTTPS и владельцу GitHub-репозитория. Для проверки неизменяемого выпуска можно использовать полный commit SHA в URL и сверить опубликованный SHA256. Ни manifest, ни хеш, полученные из того же скомпрометированного источника, не являются независимой цифровой подписью.
- Резервные копии содержат приватные ключи, ссылки и хеши паролей: они остаются под root в `/var/lib/vless-optimized/backups/`; копирование и хранение вне VPS требуют такой же защиты. Действующие реквизиты не входят в Git.
