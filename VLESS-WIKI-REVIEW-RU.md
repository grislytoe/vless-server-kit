Сайт не предоставляет в просмотренной инструкции датированного changelog: ниже возможности текущего снимка и отличия от нас, а не утверждение о датах появления каждой функции.

## Что изменилось относительно сохранённого предыдущего скрипта

В рабочем архиве сохранился предыдущий снимок с SHA256 `20c533c6f85a877c437bedbc512a0534c995e1c7bd68cf927819bc6b170a9343`: `Xray Quick Setup — VLESS REALITY (XHTTP or TCP)`. Он требовал явных domain/inbound-ip/outbound-ip, устанавливал официальный Xray через внешний shell, запускал Selfsteal/Nginx в Docker и имел опцию custom-client-hello. По сравнению с этим снимком текущий скрипт:

- Перешёл на 3x-ui, его API/SQLite, подписки и обычный системный Nginx.
- Добавил выбор TLS/REALITY и сценарий с единственным публичным IPv4.
- Использует `packet-up` и VLESS Encryption с Vision; прежний выбор xhttp/tcp в таком виде отсутствует.
- Автоматизировал выбор IP по DNS и добавил `--resume` с проверками ранее созданных реквизитов.
- Добавил UFW, ipset-списки сканеров, географическую блокировку и полное apt upgrade.

Это сравнение двух доступных снимков; точные даты промежуточных изменений и версия развернутого на вашем VPS исходного скрипта из них не следуют.

| Область | Текущий vless.wiki | Наш 1.0 |
|---|---|---|
| Панель | 3x-ui, SQLite/API, подписки и публичные параметры экспорта | Небольшая панель и ограниченный локальный root RPC, отдельные ссылки/QR |
| Профили | TLS с одним IP, TLS с двумя IP, REALITY/self-SNI с двумя IP | REALITY/self-SNI, два IP |
| Передача | XHTTP `packet-up`, Vision, генерируемая пара VLESS Encryption | XHTTP `auto`, encryption=none внутри REALITY; это не передача открытым текстом |
| IP/DNS | Определяет вход по DNS, выбирает другой публичный IPv4 для выхода | Оператор явно указывает оба IP, затем проходит проверки |
| Продолжение | `--resume`, проверка ранее созданных inbound/UUID/flow, допускается восстановление после сбоя сертификата/nginx | Повторная установка сохраняет состояние, откат управляемых файлов |
| География трафика | Добавляет blackhole для geoip:ru, category-ru и доменов ru/su/рф | Такой географической блокировки нет |
| Firewall | Включает UFW, задаёт политики и правила, сохраняет SSH; ipset-списки сканеров обновляются таймером | Firewall оператора сохраняется |
| Зависимости | Выполняет apt upgrade, скачивает 3x-ui из main и acme.sh из master без закреплённых SHA в обёртке | Xray и wheel Gunicorn закреплены с SHA256, Certbot через APT |

Преимущества vless.wiki для некоторых сценариев: готовая развитая панель/подписки, выбор профилей и возможность одного IPv4, автоматизация firewall. Для нашего сценария эти свойства не доказывают лучшую скорость или маскировку: нужны измерения из одной сети с совместимым клиентом. Vision с XHTTP требует поддержки VLESS Encryption; простая дописка `flow` к старой ссылке недостаточна. Глобальная замена профиля заставила бы проверять и переимпортировать клиенты.

Блок-листы сканеров сокращают часть известных источников зондирования, но не скрывают сервер от неизвестных адресов. Геоблокировка сокращает доступность сайтов и не является универсальным повышением безопасности. Выполнение обновлений ОС и изменение UFW — заметное расширение области изменений по сравнению с нашим установщиком.

`--resume` не является универсальным обновлением работающей установки: основной путь отказывается перезаписывать существующие Xray/3x-ui, а восстановление проверяет собственное состояние. Применять этот скрипт поверх нашего VPS для обновления нельзя.

Для 1.1 заимствована идея явного сценария продолжения/обновления с контролем идентичности. Полная миграция на 3x-ui, Vision, геоблокировка и списки сканеров автоматически не включены. Нужны отдельные стенды и согласованная смена профиля. Также на опубликованной странице на дату просмотра виден шаблон `АДРЕС_САЙТА` и сообщение локального preview: команду страницы стоит проверять перед копированием.
